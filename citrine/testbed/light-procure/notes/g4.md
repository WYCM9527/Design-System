## 一、只能猜的地方（DESIGN / AGENTS / recipes 没有规定，按自己判断决定）

### 通用
1. **左右分栏比例（Org / Roles）**：DESIGN 只有「统计卡 vs 状态条」「表单页宽度」等规则，没有「树 + 表格」「列表 + 矩阵」的分栏规则。取 `minmax(0,1fr) minmax(0,5fr)`（约 1 : 5，1440 展开侧栏时左栏 ≈ 200px、1280 折叠侧栏时 ≈ 190px）。依据：左栏内容只有「云禾科技 12」「产品设计 3」这类 6～8 字，再宽就是侧栏那条「宽度浪费」规则；右栏在 1280 下需要 ≈ 910px 才能让成员表 7 列不出现横向滚动（先试了 1 : 4，1280 下会滚动、日期列折行，于是改 1 : 5）。golden-admin 的 `Members.vue` 用的是 `240px 1fr`，但本项目禁止像素字面量，改用比例。两页用同一比例，保证「系统管理」组内两个左右分栏页对齐。
2. **筛选控件宽度写在模板 inline style（`style="width: 260px"` 等）**：DESIGN 第 6 条明说「列宽与筛选控件宽度不是 token（按内容定）」，golden-admin 所有列表页也是这么写的；硬性约束里「样式只在 `<style scoped>` 里写且不出现像素字面量」我理解为约束 `<style>` 块。折衷：`<style scoped>` 里零像素字面量，只有日期范围（260）、部门 / 状态下拉（140 / 120）三处 inline 宽度，关键词框走 `var(--layout-search-width)` 类。若集成方认为 inline 也算违规，需要给「筛选控件宽度」补一组 token（如 `layout.filter.date-range-width`）。
3. **「全部部门 / 全部状态」的值**：DESIGN 要求默认值是真实选项而非占位符，但 Element 的 `el-select` 把 `''` 当空值直接显示占位符「请选择」（实测截图确认）。所以选项值用 `'all'` 哨兵，调 API 时再换回 `''`。golden-admin 也是 `'all'`，AGENTS 没写这条坑，建议写进列表页约定。
4. **`state=error` 的实现**：复用顶栏测试工具同一机制——页面在 setup 时把 `session.failNext.list = true`，让第一次列表 / 报表加载抛一次 `ApiError`，重试即成功。没有另造一套「页面内假失败」。
5. **空态的插图层级**：范围内无数据 / 筛选无结果按 DESIGN「内容级不存在」用 `icon.muted` 线性图标 + 文案（Report 的两张图表卡、汇总表），「没有任何业务数据」（Org 无成员）才用 two-tone 品牌插图 `.empty > .illu`。Report 的空态没有画空图，图表容器换成同高（`control.height.md × 7`）的居中空态，避免版面跳动。
6. **禁用操作胶囊的原因提示**：`.act:disabled` 在配方里是 `pointer-events: none`，元素自身的 `title` 不会弹出；所以「停用」按钮外包一层 `span.act-lock[title]` 承担说明，并补 `margin-left: var(--space-inline)` 保持胶囊间距。DESIGN 只说「不可用时保留位置、压淡」，没说原因怎么给。

### P08 数据报表
7. **筛选卡只有一行筛选栏**：`.filter` 配方自带底部发丝线，单独成卡时会与卡片边线叠成双线，页面里去掉了这条 `border-bottom`。建议 recipes 给「筛选独立成卡」一个变体（如 `.filter.solo`）。
8. **动作区顺序**：`导出汇总（次要）→ 查询（主）→ 重置（quiet）`。DESIGN 只规定「查询 + 重置」这一对，导出放在它们左侧，避免次要按钮夹在主按钮与 quiet 之间。导出无数据时按钮禁用，外层 span 的 `title` 写「暂无可导出数据」（PRD §6.2）。
9. **日期范围的字段错误**：筛选栏没有可见标签也没有 `el-form`，用独立的 `el-form-item :error` 承载「请选择提交日期范围 / 最多选择 90 天」——桥接的 `is-error` 边线规则照常生效。Element 的错误文案是绝对定位在控件下方，出错时给 `.filter` 补了 `padding-bottom: spacing.8` 让文案有地方站。90 天按「含首尾的自然日」计（`diffDays + 1 > 90`）。
10. **指标卡口径说明图标的位置**：`StatCard` 没有标签插槽、也不能改（bridge 组件），只能把 `el-tooltip` 触发按钮绝对定位到卡片右上角、与标签行同高，命中区 `control.hit-min`，`aria-label` 写全「已通过金额的统计口径说明」。建议 StatCard 加一个 `#label-extra` 或 `hint` prop。
11. **指标卡骨架**：`el-skeleton` 自定义模板拼两条（标签 + 数字），骨架卡 `min-height` 用 StatCard 的内边距 + 标签行 + 数字行 + 间距的 token 算式对齐，加载完成不跳版；骨架卡不带左侧品牌指示条（它是「数据卡」特征，占位符不是数据）。
12. **趋势图 x 轴**：`MM-DD`；单序列自动带渐变面积（TrendChart 行为）。y 轴由 `trendLine` 配方 `scale: true` 决定，小整数计数会出现 1.5 / 2.5 这样的刻度（见「缺口」第 4 条）。
13. **部门排行柱状图颜色**：按任务要求不写颜色，柱子走主题 `chart.1`（品牌黄）。DESIGN「数据可视化」有「排行榜前三名纯黄、其余中性灰（sequential）」的规则，golden `Analytics.vue` 也这么做了；本页只有 4 个部门，「3 黄 1 灰」看起来像随机高亮，全黄反而干净——这是与 DESIGN 明文相悖的一处，请集成方拍板。标签颜色 / 字号取 `t.text / t.font`（token 计算值），格式 `money()`。
14. **合计行**：用 `show-summary + summary-method` 返回 `report().total`（没有把合计追加成数据行）。Element 表尾默认与正文同重、底色 `row-hover-bg`（映射到 `bg.hover`），页面里给表尾加了 `text.weight.label` + 等宽数字，让「合计」压得住正文行。
15. **无数据时汇总表也进空态**：PRD 只说指标 0 / `—`、图表空态；4 行全零 + 一条全零合计没有信息量，所以表格同样显示「所选范围内没有已提交的申请」，导出禁用。
16. **导出 CSV 金额格式**：两位小数纯数字（`toFixed(2)`），不带 `¥` 和千分位，Excel 能直接求和；通过率导出为 `50.0%` / `—`；文件名 `采购报表_2026-09-08.csv`（基准日）。
17. **图表卡头显示已生效的统计范围**（`2026-09-01 ~ 2026-09-08 · 全部部门` 中性徽标）：PRD 说图表指标表格用同一筛选结果，用户改了日期还没点查询时，这条徽标能说明图上画的是哪个范围。
18. **`state=empty` 的做法**：不伪造空结果，而是把默认范围改成上上月（种子数据从 8 月开始），走真实计算路径。代价是依赖种子数据的日期分布。

### P09 组织与成员
19. **页头位置**：任务描述把「页头行」列在右栏内容里，但 DESIGN 页面骨架规定页头由页面在最上方渲染、横跨内容区；按 DESIGN 做成全宽页头，副文案 = 企业名 · 共 N 人（全员）· 启用 M 人；右栏卡头再显示当前节点（「全部成员」/「技术 · 成员」）与该范围筛选后的人数。
20. **组织树的选中态**：Element `el-tree--highlight-current` 的当前节点底色是 `--el-color-primary-light-9`，桥接把它映射为 `bg.selected-subtle`（neutral-100）——走了 token，但与 hover（`bg.subtle` / `bg.hover`）几乎同色，看不出「当前」。页面用 `:deep` 改成深黑反转块（`action.selected` + `text.on-selected` + 500），理由：树在这里是导航面，与侧栏、Roles 左侧列表同一语义；DESIGN 里「级联 / 树选择的面板」那行写的是「当前 `text.selected` + 加重」，但那是下拉面板的规则，页面级树没有规则。展开箭头在选中块上改成白色。
21. **树行高与圆角**：`--el-tree-node-content-height` 从 Element 默认 26px 改为 `control.height.md`（34），行圆角 `radius.md`，节点数在行右侧 `text.small + text.muted`。节点计数 = 该部门全部成员（含停用），与状态筛选「全部」时的表格一致。
22. **新增成员时部门预填当前选中的部门节点**：PRD 没说，但在「技术」节点下点新增，部门默认技术更顺手；选公司节点时留空必选。
23. **姓名列「标题型」**：近黑 + 500 的纯文本，不做链接——本项目没有成员详情页，点击无处可去。当前登录账号那行在姓名下方加 `.sub`「当前登录账号」，解释为什么它的「停用」是灰的。
24. **角色列**：管理员 `.badge.brand`（DESIGN「强调徽标（置顶、管理员等角色）」），其余用 `.badge.neutral`，避免一列里徽标与裸文字混排。成员状态胶囊：启用 `success`、停用 `neutral`（无倾向状态用 neutral 的规则）。
25. **弹窗宽度**：按任务用 `layout.modal.width.sm`（420）。DESIGN 写的是「确认类弹窗 sm、带表单的弹窗 md」，这里 4 个字段单列在 420 下够用（输入框约 250px），但与 DESIGN 明文不一致，请拍板。
26. **角色控件**：3 个角色用 `el-radio`（圆形单选）而不是分段选择器——它是表单字段，DESIGN 的分段配方是「视图 / 状态切换」。角色下方 `.help` 显示该角色的 `desc`，编辑时追加「下一次切换为该成员时采用新角色」。编辑当前账号时角色渲染为只读输入框（`bg.readonly` + `text.secondary`）+ 说明，不是禁用态（DESIGN：只读 ≠ 禁用）。
27. **邮箱唯一性双保险**：本地 rules 先查一遍 `db.members`（忽略大小写、排除自己）给即时反馈；服务层 `ApiError.code === 'duplicate'` 再落到同一字段（`:error`）。
28. **停用 / 启用**：停用走 `ElMessageBox.confirm`，确认按钮 `confirmButtonClass: 'el-button--danger'`（golden 先例）；启用直接执行。成功提示「已停用 沈叶」/「已启用 …」。最后一名管理员的保护没有前置禁用，交给服务层 `ApiError` 用 `ElMessage.error` 提示（任务要求），只有当前账号那行前置禁用。

30. **`state=invalid` 配合 `dialog=new`**：打开弹窗后自动 `validate()`，方便截「字段错误」。

### P10 角色权限
31. **左侧列表用自绘 `<button role="tab">` 而非 `el-menu`**：`el-menu` 的选中项自带侧栏语义的黄色指示条、且 `el-menu-item` 不透传属性。选中态选用 **`--color-action-selected` / `--color-text-on-selected`**（深黑反转块 + 500），而不是 `--color-bg-selected` / `--color-text-selected`：后者在亮色下 `bg.selected` 与 `bg.hover` 都是 neutral-100，选中与悬停完全同色，无法区分；前者与侧栏、分段选择器、Org 树保持同一「选中 = 反转块」语义。不加黄色指示条（DESIGN 说指示条「最多」留给旁边，非必需）。

33. **「是否可用」列的表达**：`CheckOne`（`status.success` 色）+「可以」/ `—` +「不可以」，文字与图标同时出现；不可用行的文字整体降为 `text.muted`（颜色只是辅助，文字仍在）。
34. **补充规则的落点**：PRD §2 的 5 条补充规则（管理员不自动获得审批权、本人不能自审、复制不改原单、供应商可选≠可管理、两名审批人）既写进对应单元格的 `.sub` 说明，也在表格下方列成「补充规则」小节，保证「严格对应 PRD §2」可核对。
35. **顶部 `el-alert` 里放了导览链接**「前往组织与成员 ›」（`.go`）：PRD 只要求那句话，加链接是因为文案本身就在指路。
36. **卡头右侧的摘要**「启用成员 N 人 · 可用模块 M / 11」是自加的，帮助一眼比较三个角色。

## 二、数据层 / 骨架缺口

1. **`api.report()` 无法使用（阻断级）**：它按日迭代用的 `addDay(d)` 是「`new Date(d + 'T00:00:00+08:00')` → `setDate(+1)` → `toISOString().slice(0,10)`」，`toISOString` 取 UTC 日期，结果永远等于 `d` 本身（与运行机器时区无关），`for (d = from; d <= to; d = addDay(d))` 不会终止，最终 `RangeError: Invalid array length`（首轮冒烟实测）。页面内写了口径完全相同的 `fetchReport()`（范围内已提交、草稿不计、部门取申请内快照、通过率 = 已通过 ÷（已通过 + 已驳回）、`byDept` 按已通过金额倒序、`total` 合计行），并复用 `session.failNext.list` 作为失败注入、保留 200ms 延迟。数据层修复后把 `fetchReport` 换回 `report` 即可（一行）。
2. **`format.addDays()` 同样错位**：`addDays(d, 1)` 返回 `d`，`addDays(d, -1)` 返回 `d - 2`（同一 `+08:00` 构造 + `toISOString` 的问题；`diffDays` 因两端同偏移不受影响，`monthStart` 是纯字符串运算没问题）。`api.myWeeklyTrend()` 的周区间也用了同样写法，会整体偏一天（不在我负责范围，只提示）。页面内用 UTC 字段运算的 `shiftDays()` 代替。建议 `format.js` 统一改成 `setUTCDate` / `getUTCDate` 或直接字符串日期运算。
3. **`constants.js` 没有成员（与供应商）启停用的状态 → 文案 / tone 映射**：`APP_STATUS`、`ASSET_STATUS` 有，`active: boolean` 没有。页面内就地定义 `{ 启用: success, 停用: neutral }`；建议补 `ACTIVE_STATUS`，供应商页也会用到。
4. **`TrendChart` / `trendLine` 对计数类数据不友好**：`yAxis.scale: true` + `splitNumber: 4` 让 1～3 这样的小整数出现 1.5 / 2.5 刻度（截图可见）。TrendChart 不接受任何 option 覆盖，页面无法加 `minInterval: 1`。建议 `trendLine` 增加 `integer`（或 `minInterval`）参数，或数据全为整数时自动设置。
5. **`EChart` / `TrendChart` 不监听 option 变化**：只在挂载与主题切换时 `setOption`，重新查询后图不会更新。页面用 `:key="seq"`（每次查询 +1）强制重建实例。建议 EChart 内部 `watch(() => props.option, render)`。
6. **`StatCard` 没有标签旁的插槽 / 提示 prop**：见上文第 10 条，只能绝对定位一个图标按钮压在卡片上。
7. **`.filter` 配方单独成卡时的底线**：见第 7 条，需要一个变体。
8. **`.act` 禁用态与 `title`**：`pointer-events: none` 让原因提示无处附着，见第 6 条；如果这是常见需求，recipes 可以约定「禁用胶囊外包 `.act-lock[title]`」或改用 `aria-disabled` 而不是 `pointer-events`。
9. **`el-select` 的空值哨兵**：AGENTS「下拉默认值是真实选项『全部…』」需要补一句「值不能是 `''`，用 `'all'` 再映射」。
10. **`downloadCsv` 的列定义支持 `get`**，够用；但没有「导出成功」的统一提示约定，页面自己 `ElMessage.success('已导出 N 个部门的汇总与合计行')`。
11. **`guard.mjs` 只校验 design-system 构建一致性**，不扫描页面里的色值 / 像素字面量（那是 `status` 工具的事，本项目没接），所以本报告里「零字面量」是自查结论，不是工具结论。
12. **`useDirtyGuard` 只接受一个 `isDirty`**：设置页两个页签各自脏检查 + 页签切换确认要页面自己用 `el-tabs before-leave` + `confirmLeave` 拼；工作正常，只是提一下没有「多表单」封装。

## 三、组件库与规则的冲突

1. **`el-tree` 当前节点底色**：`--el-color-primary-light-9` → 桥接映射 `bg.selected-subtle`，与 hover 几乎同色，不满足「当前一律深黑反转块或近黑文字」；桥接没有接管 `.el-tree-node.is-current`，只接了拖拽相关的两条。页面 `:deep` 覆盖（第 20 条）。建议桥接补：`.el-tree--highlight-current .el-tree-node.is-current > .el-tree-node__content { background: action.selected; color: text.on-selected; font-weight: medium }`（或至少 `text.selected + 加重`），以及 `--el-tree-expand-icon-color` 从 `text.placeholder`（2.5:1）改为 `icon.muted`。
2. **`el-tree` 行高**：默认 26px 不在 `control.height.*` 任何一档，页面改成 md。建议桥接把 `--el-tree-node-content-height` 接到 `control.height.md`。
3. **`el-select` 单选把 `''` 当空值**：见二-9；这是「默认值必须是真实选项」规则与组件行为的直接冲突。
4. **`el-table` 表尾（`show-summary`）**：底色用 `--el-table-row-hover-bg-color`（映射到 `bg.hover`），字重与正文相同——DESIGN 没有「合计行」配方，桥接也没接管。页面加了 `text.weight.label`。建议在表格配方里定义合计行：`bg.subtle` + 500。
5. **`el-form-item` 的错误文案是绝对定位**：在没有 `margin-bottom` 的筛选栏里会压到卡片边线，需要页面在出错时补内边距；在普通表单里则会与 `.help` 叠加，需要页面隐藏 `.help`。DESIGN「错误文案占同一位置」的规则组件并不天然满足。
6. **`el-dialog` 的 `width` 只能通过 `:width="'var(--layout-modal-width-sm)'"` 传 CSS 变量字符串**（Element 把它塞进 `--el-dialog-width`），能用但写法别扭，桥接可以按尺寸类（如 `.el-dialog.is-sm`）接好。
7. **`el-alert` 的图标**是 Element 自带 SVG，与 IconPark 并存（DESIGN 已接受这种妥协）；`type="info"` 经桥接变成青色成对（不是 Element 的灰），符合规则。
8. **`.act:disabled` 的 `pointer-events: none`** 与「图标 / 禁用控件要有可访问的原因说明」相冲：既不能 hover 出 `title`，也不能作为 `el-tooltip` 触发器；只能外包一层。
9. **`el-radio-group` 在 `el-form-item__content` 里默认 `align-items: center`**，这里没问题（单行）；但 `.help` 要换行必须 `width: 100%`，否则会与单选组同行挤在一起。
10. **`el-input type=file` 不存在，Element 的 `el-upload` 会带上传列表与自己的样式**；按任务用原生 `<input type=file hidden>` + 次要按钮触发，避免 `el-upload` 的拖拽区样式与「仅一张 Logo」的场景不匹配。
11. **`el-tabs__item` 标题里追加「（未保存）」会改变标签宽度**，Element 的下划线 `active-bar` 会随之重算位置，有一帧位移；可接受。
12. **`el-message-box` 的确认按钮是 `primary + danger` 双类**，桥接已处理文字色；`confirmButtonClass: 'el-button--danger'` 是 golden 先例，能得到红底白字的危险确认。
13. **`el-tooltip` 触发器需要可聚焦元素**：用 `<button aria-label>` 而不是裸图标，DESIGN「Tooltip 不算可访问名称」的规则因此成立。
