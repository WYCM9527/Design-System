## 二、数据层 / 骨架缺口与绕法

1. `guard.js useDirtyGuard`：`onBeforeRouteLeave` 绑定 setup 时的路由记录，new → edit `replace` 复用实例后不再触发。绕法：页面补全局 `router.beforeEach`（见上 20）。建议 guard.js 改为注册全局守卫 + 卸载移除，或在 `RouterView` 上按 `route.name` 加 key。
2. `api.submitApplication`：注入失败在 `saveDraft` 之前抛出（好），但「供应商已停用」是在 `saveDraft` 之后抛——新建表单会留下一张草稿却拿不到 id，重试会重复建单。绕法：页面提交前先校验停用供应商，不让它到 api。建议 api 先校验再保存。
3. `api.getApplication` 不做权限判断，任何 id 都返回；页面自己判 `applicantId === 当前用户` 与 `canEditApp`。
4. `session.js` 没有「当前用户 id」的直接导出，用 `user.value.id`。
5. `constants.js` 没有附件写入状态的文案 / tone 映射，页面内定义 `FILE_STATE`（写入中 info / 已就绪 success / 失败 error）。
6. `recipes.css` 缺的配方（本页在 scoped 里写了，建议提升）：表单内可编辑表格（紧凑内边距、顶部对齐、行内错误小字、列头星号）、上传区 `.upload-zone` 与附件列表行、sticky 表单操作条、表单骨架、抽屉分组小标题 `.drawer-h`（golden-admin 每页各写一份，本项目也会重复）、`.nowrap`。
7. `el-select` 把 `''` 当空值显示占位符，而 api 用 `''` 表示不过滤：页面用 `all` 哨兵并在查询前映射。
8. `TableSkeleton` 的列宽只能传 px 数字（props），与「无像素字面量」规则天然冲突，属不可避免。
9. `/tmp/lp-console.mjs` 引用的 `golden-admin/tools/lib/cdp.mjs` 不存在，实际在 `citrine/tools/lib/cdp.mjs`；本组另写了 `/tmp/lp-smoke-g2.mjs` 等（不入库）。

## 三、组件库（Element Plus 2.14）与规则的冲突

1. `el-form-item__error` 绝对定位在控件下方：放进 `el-table` 单元格会被 `.cell` 的 `overflow: hidden` 裁掉 → 用 `#error` 插槽改成静态文字。同理 DESIGN「帮助文字与错误占同一位置不叠加」无法自动成立，只在没有校验规则的字段（优先级）放帮助文字，其余用占位符 / 字数提示代替。
2. 无 label 的 `el-form-item` 内容区行高被桥接定为 `control.height.md`（34），会把 small 控件行撑高 → 行内 form-item 传 `size="small"`。
3. `el-table` 单元格内边距 token（20 × 2）对可编辑表过宽（见一 · 4）；`td` 默认 `vertical-align: middle` 让出错行的控件上下漂移 → 改 top。
4. `el-input-number`：`:min="0.01"` 会把用户输入的 0 静默夹成 0.01、`:precision="2"` 静默四舍五入第三位小数，规则里「必须 ≥ 0.01」「最多两位小数」的错误文案实际不会出现（被组件修正掉了），只有清空才会报「请输入」；small + `controls-position="right"` 时两个箭头各约 14px 高，低于 `control.hit-min`（24）。
5. `el-select` 的 `''` 值被视为空（见二 · 7）。
6. `el-drawer` 的焦点陷阱：打开后焦点落在容器而不是第一个可聚焦元素，需要 `@opened` 手动聚焦；关闭时 Element 会尝试把焦点还给打开前的元素（源码 `tryFocus(lastFocusBeforeTrapped)`），× / Esc 关闭后焦点确实回到了触发按钮（页面兜底与 Element 同时作用，未能单独验证 Element），但处理成功后列表刷新、触发行被重绘时它会失败（焦点掉到 body），必须由页面兜底（见一 · 30）。Tab 顺序按 DOM 是 body → footer，关闭按钮（×）夹在正文与页脚之间。
7. `el-drawer` 默认标题是纯文本，单号要 `.mono` 只能用 header 插槽自绘 `h3`（沿用 `titleId` / `titleClass` 保住 `aria-labelledby`）。
8. `el-tabs` 必须有 `el-tab-pane` 才渲染页签项；内容放在页签外共用时要隐藏空的 `.el-tabs__content`。
9. `ElMessage` 各 type 被桥接统一为深底反转、图标隐藏，`success / warning / error` 只能靠文案区分。
10. 抽屉内的离开确认走 `ElMessageBox`，等于第二层浮层，与 PRD §1.1「浮层内确认用原位确认区域」冲突；按任务与 AGENTS（`before-close` 走 `confirmLeave`）执行，此处登记。
11. `el-date-picker` 的「今天」高亮跟真实系统日期（2026-09-14）走，与演示基准日 2026-09-08 不一致；`default-value` 只能定位面板月份，改不了「今天」。
12. `el-button` 同时 `loading` 与 `disabled` 时桥接的 `opacity.disabled` 会把正在加载的按钮也压淡 → 只禁用「另一个」按钮，加载中的按钮不加 disabled。
13. `el-upload` 未采用：其拖拽区与列表 hover 已被桥接接管，但列表项表达不了「写入中 / 失败」状态与预览 / 删除胶囊，自绘更省。
14. `el-descriptions` 的 `label-width` 接受 `var(--layout-form-label-width)` 字符串，正常；`show-overflow-tooltip` 的深色 popper 走桥接 `is-dark`，正常。
