# 轻采｜企业采购与资产后台

**产品需求文档 · V1.0 · 虚拟测试项目**  
面向：产品、设计、前端、后端与测试  
文档日期：2026-09-08  
本版范围：12 个页面、3 类角色、单级审批、桌面端

> 本文定义一个可以完整走通的中后台测试产品。业务围绕“员工申请采购、审批人处理、管理员维护资产和基础资料”展开。页面类型尽量完整，流程、数据量和权限模型保持精简。

## 1. 产品背景与目标

一家约 50 人的虚拟企业，希望统一管理办公设备采购申请和现有资产，解决申请散落、审批进度不清、资产归属难查的问题。

产品的主要使用者：

- 员工：提交采购申请，查看进度和自己领用的资产。
- 审批人：集中处理采购申请，查看采购统计。
- 管理员：维护资产、供应商、成员和系统配置。

本次测试希望验证三个结果：

1. 列表、表单、详情、图表、树形结构、抽屉和弹窗等典型页面能够统一呈现。
2. 创建、提交、审批、登记与领用等关键操作可以形成闭环，状态和数据保持一致。
3. 空数据、加载失败、表单错误、无权限等情况都有明确反馈。

### 1.1 范围与复杂度限制

| 项目 | 本版约定 |
| --- | --- |
| 业务主体 | 一家公司，部门结构固定为两层：公司 → 部门 |
| 审批 | 一个共享审批队列，一位有资格的审批人处理后结束 |
| 金额 | 人民币，保留两位小数，不计算税费、折扣或预算占用 |
| 采购明细 | 每张申请最多 5 行 |
| 页面深度 | 菜单页进入表单或详情后，不再增加下一级业务页面 |
| 浮层深度 | 同时最多一个抽屉或弹窗；浮层内确认用原位确认区域 |
| 设备 | 以 1440px 桌面为设计基准，兼容 1280px；不单独设计手机端 |
| 数据与账号 | 全部为虚拟数据；测试版提供演示身份切换 |
| 默认实现条件 | 可使用本地模拟数据；业务修改、设置和新增附件应在刷新后保留 |

**本版不包含：**真实登录注册、多租户、多级审批、流程设计器、撤回与转交、采购订单、合同付款、发票、仓储出入库、资产折旧维修、批量导入、自定义报表、真实邮件短信和第三方对接。

采购审批通过只代表申请获准。资产由管理员单独登记，可选关联已通过的申请，审批不会自动生成资产。

## 2. 角色与权限

固定三个系统角色，不支持创建或修改角色权限。成员可以更换角色，角色权限页用于查看权限关系。

| 能力 | 申请人 | 审批人 | 管理员 |
| --- | --- | --- | --- |
| 工作台 | 查看本人数据 | 查看本人数据 | 查看本人数据 |
| 创建采购申请 | 可以 | 可以 | 可以 |
| 查看采购申请 | 仅本人 | 全部 | 全部 |
| 编辑、提交、删除草稿 | 仅本人的草稿 | 仅本人的草稿 | 仅本人的草稿 |
| 复制申请 | 仅本人可见的申请 | 仅本人可见的申请 | 仅本人可见的申请 |
| 处理审批 | 不可以 | 可以，排除本人申请 | 不可以 |
| 资产台账 | 仅查看本人在用资产 | 查看全部 | 查看并管理全部 |
| 供应商管理 | 无菜单入口 | 无菜单入口 | 查看并管理 |
| 数据报表 | 无入口 | 查看全部采购统计 | 查看全部采购统计 |
| 组织与成员、角色权限、系统设置、操作日志 | 无入口 | 无入口 | 查看并管理；角色权限只读 |
| 导出采购、资产和报表 | 不可以 | 可导出自己有权查看的数据 | 可导出自己有权查看的数据 |

补充规则：

- 所有人在采购表单中都能选择启用的供应商；这不代表拥有供应商管理权限。
- 复制任意可见申请时，生成一张属于当前用户的新草稿，不改变原申请。
- 隐藏无权限菜单和按钮。直接访问无权限页面时显示“暂无访问权限”，提供返回工作台入口。
- 管理员角色不自动获得审批权。本人申请也不能由本人审批。
- 初始演示数据包含两名启用审批人，便于验证审批人提交的申请由另一人处理。若测试中更改了这些角色，进行审批用例前先恢复演示数据。

## 4. 核心业务与状态

### 4.1 主流程

**采购申请列表 → 填写并提交 → 审批人通过或驳回 → 申请人查看结果。**

填写页可以直接提交，也可以先保存草稿。审批通过后，本版采购流程结束。

| 当前状态 | 可执行操作 | 操作后状态 | 条件 / 说明 |
| --- | --- | --- | --- |
| 草稿 | 编辑、保存草稿 | 草稿 | 仅申请人本人；保存草稿只强制校验标题，已填写字段仍须符合格式 |
| 草稿 | 提交申请 | 待审批 | 仅申请人本人；所有必填项和明细均校验通过 |
| 草稿 | 删除 | 记录移除 | 仅申请人本人；二次确认 |
| 待审批 | 通过 | 已通过 | 审批人操作，且申请人不是自己；意见选填 |
| 待审批 | 驳回 | 已驳回 | 审批人操作，且申请人不是自己；意见必填 |
| 已通过 / 已驳回 | 查看、复制 | 原记录不变 | 复制后进入一张新草稿的编辑页 |

状态只有“草稿、待审批、已通过、已驳回”四种。已提交的申请不允许编辑、删除或撤回。驳回后需要修改时，使用“复制为新申请”，再次提交。

所有可见申请都可复制；复制只带入标题、明细、用途、备注和仍然启用的供应商。不复制附件、期望日期、申请人、单号、审批意见与历史记录。

### 4.2 资产辅助流程

**管理员登记资产（闲置） → 分配给成员（在用） → 确认归还（闲置）。**

一条资产代表一件实物，不使用数量字段。资产只设“闲置、在用”两种状态，状态由分配和归还操作产生，不能直接修改。

分配时必选一名启用成员；归还时清空当前使用人，但保留分配和归还历史。资产不支持删除、报废、转移或批量分配。

## 5. 页面需求

### P01 工作台

**目的：**让当前用户快速了解自己的申请和资产情况，进入下一步操作。

页面从上到下包含：

1. 欢迎区：用户姓名、所属部门、当前日期，以及“新建采购申请”。
2. 四个指标卡：我的申请总数、我的待审批申请、我的本月获批金额、我的在用资产。
3. 两个图表：近 6 周本人提交申请数量趋势；本人全部申请的状态分布。
4. 我的最近申请：最多 5 条，展示标题、金额、状态、更新时间，可进入详情。
5. 审批人额外显示“待我审批”：最多 5 条，排除本人申请；“查看全部”进入审批中心。

指标口径：申请总数包含草稿；本月获批金额按审批通过时间统计；趋势按提交时间统计；资产按当前使用人统计。指标卡分别进入本人申请列表、本人待审批列表、本人本月获批列表和本人在用资产列表，并带上对应条件。

图表悬停显示准确数值，不支持下钻。无数据时显示零值和引导，不绘制虚构趋势。申请记录为空时提供“新建采购申请”按钮。

### P02 采购申请

**目的：**查找申请，掌握进度，管理自己的草稿。

| 区域 | 内容 |
| --- | --- |
| 页面头部 | 标题、申请总数、新建采购申请、导出 |
| 搜索筛选 | 关键词（单号 / 标题）、状态、所属部门、申请人、提交日期范围、通过日期范围 |
| 默认筛选显示 | 关键词、状态、所属部门、提交日期；“展开筛选”后显示申请人和通过日期 |
| 表格字段 | 复选框、申请单号、标题、申请人 / 部门、总金额、优先级、状态、提交时间、操作 |
| 行操作 | 查看；本人的草稿额外显示编辑、提交、删除；复制收进“更多” |
| 批量操作 | 仅“删除我的草稿” |
| 默认排序 | 更新时间倒序；可按总金额排序 |

申请人看不到部门和申请人筛选，因为数据固定为本人。工作台传入的条件显示为可移除标签，隐藏筛选项的已选值也必须可见。

筛选点击“查询”后生效；“重置”清空全部条件并回到第一页。更换排序或查询条件时回到第一页。关键词匹配单号或标题中任意部分。

只有本人的草稿行可以勾选，其他行的复选框禁用。全选只选择当前页符合条件的草稿，跨页或重新查询后清空选择。删除确认显示数量，例如“确认删除这 3 张草稿？”

### P03 新建 / 编辑采购申请

**目的：**在单页完成申请，不设置分步向导。

页面使用“基础信息 → 采购明细 → 附件与备注”的顺序，底部固定“取消、保存草稿、提交申请”。提交时在当前页展示错误，不另设确认页。

| 字段 | 控件 | 必填与规则 |
| --- | --- | --- |
| 申请标题 | 单行输入 | 必填，去除首尾空格后 2–50 字 |
| 申请人、所属部门 | 只读文本 | 取当前用户资料；生成申请时保存快照 |
| 优先级 | 单选 | 普通 / 紧急，默认普通；紧急只影响展示，不改变审批流程 |
| 期望到货日期 | 日期选择 | 提交时必填，不早于演示基准日；不参与资产流程 |
| 供应商 | 可搜索单选 | 选填，仅能选择启用供应商 |
| 采购用途 | 多行输入 | 提交时必填，10–300 字 |
| 附件 | 拖拽 / 点击选择 | 选填，最多 3 个，每个不超过 5MB，支持 JPG、PNG、PDF |
| 补充备注 | 多行输入 | 选填，最多 300 字 |

采购明细支持添加和删除，保留至少 1 行，最多 5 行：

| 明细字段 | 规则 |
| --- | --- |
| 物品名称 | 必填，1–50 字 |
| 类别 | 必选：电脑设备、办公设备、办公家具、其他 |
| 规格说明 | 选填，最多 100 字 |
| 数量 | 必填，1–99 的整数，默认 1 |
| 预估单价 | 必填，0.01–99,999.99 元，最多两位小数 |
| 小计 | 自动计算：数量 × 预估单价，只读 |

底部展示总数量、预估总金额。计算精确到分；未填完整的行显示“小计 —”，汇总标明“暂计”，提交时不允许有不完整明细。

交互要求：

- 新建页仅填写合法标题即可保存草稿；提交必须完成所有必填项。编辑草稿时，已停用供应商显示“已停用，请重新选择或清空”，提交前必须处理。
- 添加第 5 行后禁用添加按钮，并显示“最多添加 5 项”；剩 1 行时禁用删除。
- 上传区域展示文件名、大小、处理状态、删除和预览入口。图片支持预览，PDF 可在独立预览标签打开；失败可移除后重选。
- 上传未完成或失败时不允许提交，并在附件区域说明原因。超出类型、大小或数量限制时保留已成功选择的附件。
- 点击提交后按钮进入处理中，防止重复提交；失败保留输入，成功进入详情并显示“申请已提交”。
- 有未保存修改时，通过返回、取消或导航离开需确认；未修改时直接返回。保存后刷新仍能找到该草稿及附件。

### P04 采购申请详情

**目的：**集中说明“申请了什么、现在到哪一步、谁处理过”。

顶部摘要：标题、单号、状态标签、总金额、申请人、提交时间，以及当前用户可执行的操作。

使用两个页签：

- **申请信息：**基础信息、采购明细表、金额汇总、采购用途、附件、备注。选填字段为空统一显示“—”。
- **流转记录：**按时间倒序展示创建、提交、通过或驳回事件，包括操作者、时间和审批意见；反复保存草稿不重复堆积业务事件。

已驳回时，摘要下方突出显示驳回原因。已通过时显示审批人和通过时间。草稿未提交时，提交时间显示“未提交”。

操作遵循第 2、4 节权限和状态规则。审批人在详情点击“通过 / 驳回”时打开处理弹窗，校验与审批中心一致。复制草稿后跳转编辑页，不叠加详情窗口。

申请人和部门使用创建时的资料快照，供应商使用提交时的资料快照。后续基础资料变化不能改变历史申请的展示含义；采购列表部门筛选和报表分组也使用申请内的部门快照。

### P05 审批中心

**目的：**让审批人快速阅读和处理申请。

仅审批人可进入，使用“待我审批、我已处理”两个页签。

- 待我审批：全部待审批申请，排除自己提交的申请。
- 我已处理：由当前审批人完成的通过或驳回记录。
- 搜索筛选：单号 / 标题、部门；已处理页签额外支持审批结果。
- 列表字段：单号、标题、申请人 / 部门、总金额、优先级、提交时间；已处理增加结果和处理时间。
- 待审批默认紧急优先，同优先级按提交时间从早到晚排列；已处理按处理时间倒序。

点击“处理”打开右侧宽抽屉，展示基础信息、用途和明细；附件只展示清单，需要预览时使用“查看完整详情”离开抽屉进入 P04。

抽屉底部为审批意见和“通过、驳回”。通过意见选填，驳回意见必填，填写时为 2–200 字。点击按钮即提交，不再叠加确认弹窗。

成功后关闭抽屉，更新列表和数量，记录移入“我已处理”，并生成结果通知。失败则保留意见，可重新提交。同一申请只允许成功处理一次；若已被其他审批人处理，提示“该申请已处理，请刷新列表”，停止提交。

不提供批量审批、转交、加签、撤回或自动处理下一条。

### P06 资产台账

**目的：**查询资产归属，完成简单登记、分配与归还。

| 区域 | 内容 |
| --- | --- |
| 搜索筛选 | 关键词（资产编号 / 名称）、类别、状态、使用部门 |
| 表格字段 | 资产编号、名称 / 规格、类别、购入金额、状态、使用人 / 部门、登记日期、操作 |
| 顶部操作 | 管理员可新增资产；审批人、管理员可导出 |
| 行操作 | 查看；管理员额外可编辑，闲置时可分配，在用时可归还 |

申请人仅显示自己的在用资产，隐藏状态和使用部门筛选。审批人只读。由工作台“我的在用资产”进入时，带入“使用人＝当前用户、状态＝在用”条件并显示筛选标签；审批人和管理员可以清除标签回到全部可见资产，申请人的本人范围不可解除。

新增和编辑使用抽屉，字段包括：名称（必填，1–50 字）、类别（必填，与采购明细一致）、规格（选填，100 字内）、购入金额（必填，0.01–99,999.99 元）、购入日期（必填，不晚于基准日）、存放位置（必填，1–50 字）、来源申请（选填）、备注（选填，300 字内）。

资产编号由系统生成，不可编辑。来源申请只允许选择已通过的申请，可一单关联多件资产；不校验与采购数量或金额的一致性。关联只用于追溯，不回写采购单。在用资产编辑基础资料时不改变使用人和状态。

详情抽屉分“资产信息、使用记录”两个页签。当前用户有权查看来源申请时，点击跳转 P04，关闭资产抽屉，返回时恢复原列表；无权查看时仅显示“已关联采购申请”，不显示单号、标题或链接。

分配使用一个小弹窗：启用成员选择器、只读部门、备注。确认后变为在用。归还使用确认弹窗，确认后变为闲置。存放位置保留原值，可另行编辑。不支持在用状态下直接更换使用人。

### P07 供应商管理

**目的：**维护采购表单可选择的供应商。

- 搜索筛选：供应商名称 / 联系人、状态。
- 表格字段：供应商名称、联系人、联系电话、联系邮箱、状态、更新时间、操作。
- 操作：新增、查看、编辑、启用 / 停用；不提供删除或批量操作。
- 新增、编辑共用抽屉：供应商名称必填且去空格后唯一，2–50 字；联系人必填，1–20 字；电话选填，7–20 位数字及常用符号 `+ - ( ) 空格`；邮箱选填并校验格式；地址、备注各选填，200 字内。
- 新建默认启用。停用需确认，并说明“停用后不可用于新申请，历史申请不受影响”。启用直接执行并提示成功。

供应商停用后从新申请选择器中移除。历史已提交申请仍可展示原供应商快照；草稿按 P03 规则重新确认选择。

### P08 数据报表

**目的：**提供一页能够核对来源的采购统计。

顶部使用“提交日期范围、所属部门、查询、重置、导出汇总”控件；日期范围必填，默认本月，最多选择 90 个自然日。筛选对象为范围内已提交的申请，草稿不进入报表。

页面内容：

1. 四个指标：提交申请数、申请总金额、其中已通过金额、通过率。
2. 申请趋势：按提交日展示申请数量，可悬停查看每日数量。
3. 部门金额排行：横向柱状图，展示各部门已通过金额。
4. 汇总表：部门、申请数、申请金额、已通过数、已通过金额、通过率，并有合计行。

**口径：**通过率 = 已通过数 ÷（已通过数 + 已驳回数），分母为零显示“—”。金额使用申请中的预估总金额，不代表付款或实际资产成本。

报表的“已通过金额”统计所选提交日期范围内、当前为已通过的申请；工作台“本月获批金额”按通过时间统计，二者口径不同，分别提供说明提示。图表、指标和汇总表在本页内使用同一筛选结果。

不支持图表下钻、自定义维度、保存视图或报表订阅。

### P09 组织与成员

**目的：**通过组织树查找成员，维护角色与可用状态。

左侧固定公司与四个部门的树，右侧显示选中范围的成员表格。点击公司显示全部，点击部门显示该部门。部门不支持新增、编辑、排序或删除。

顶部支持姓名 / 邮箱搜索和状态筛选，管理员可新增成员。表格包含姓名、邮箱、部门、角色、状态、加入日期、操作。

新增、编辑使用弹窗：姓名必填，2–20 字；邮箱必填、格式合法且忽略大小写后唯一；部门必选；角色必选，默认申请人。新成员默认启用，保存后加入本地演示账号列表，不发送邀请。

成员只支持编辑和启用 / 停用，不支持删除、重置密码或兼任多个部门。停用后不能切换为该身份，也不能被分配资产，历史申请和资产归属仍保留。成员调换部门后，其在用资产的当前使用部门同步更新；采购申请和资产使用历史中的部门快照保持原值。

禁止停用当前操作账号或修改其角色；禁止通过停用或角色修改移除最后一名启用管理员。其他成员角色调整保存后，下一次切换为该成员时采用新角色。启停用操作记录日志。

### P10 角色权限

**目的：**清楚展示“不同身份能够看到什么、执行什么”。

左侧为申请人、审批人、管理员三个角色，显示各角色启用成员数；右侧显示角色说明与权限矩阵，内容严格对应第 2 节。

权限以业务模块分组，区分查看范围和可执行操作。可使用只读复选标记与文字说明，不能只靠颜色表达。页面顶部显示“系统预置角色，权限不可编辑”，不出现无实际功能的保存或新增按钮。

角色调整在成员页面完成。本页不实现自定义权限树、字段权限、数据范围配置和权限继承。

### P11 系统设置

**目的：**覆盖常见设置表单，同时让每个可修改字段都有可观察效果。

使用“基础设置、通知设置”两个页签，每个页签独立保存；有未保存修改时切换页签需要确认。

| 设置 | 默认值 / 规则 | 保存后的效果 |
| --- | --- | --- |
| 系统名称 | 轻采，必填，2–20 字 | 更新侧栏品牌名称 |
| 企业名称 | 云禾科技，必填，2–30 字 | 更新组织树根节点名称 |
| 企业 Logo | 选填，PNG / JPG，最大 2MB | 更新侧栏标识；移除后恢复文字标识 |
| 列表每页条数 | 10 / 20 / 50，默认 10 | 下一次打开完整列表页时采用新默认值 |
| 审批结果站内通知 | 默认开启 | 决定之后是否为申请人创建审批结果通知 |

保存后显示成功提示；失败保留修改。每页条数不影响工作台“最多 5 条”的摘要列表。关闭通知不会删除已有消息，也不会影响申请流转记录。

底部提供“恢复演示数据”，仅管理员可用，独立于表单保存。明确提示将清空本次测试新增或修改的数据、附件、通知与日志，恢复初始数据和设置；输入“恢复”后执行，完成后回到管理员工作台。

### P12 操作日志

**目的：**查询关键操作，辅助测试定位结果。

- 筛选：关键词（对象编号 / 名称）、操作人、模块、操作日期。
- 表格字段：操作时间、操作人、模块、操作类型、操作对象、摘要。
- 默认按时间倒序，支持分页。只读，不提供编辑、删除或导出。
- 点击记录打开详情抽屉，展示操作前后摘要。例如“资产状态：闲置 → 在用；使用人：— → 林晓”。

记录成功的申请创建、草稿保存、提交、删除、审批，以及资产登记 / 编辑 / 分配 / 归还、供应商和成员新增 / 编辑 / 启停用、系统设置变更。复制申请记作新草稿创建。

不记录输入过程、普通页面浏览、搜索、文件预览或导出；失败操作通过当前页面报错，不要求形成审计记录。恢复演示数据后只保留预置日志。

## 6. 全局交互与展示规则

### 6.1 页面框架

- 左侧导航支持展开和收起；当前菜单有明确选中态。
- 顶部显示面包屑、站内通知入口、当前姓名与角色、演示身份切换。
- 演示身份切换展示启用成员；切换成功后返回工作台，清除上个身份的页面筛选和临时选中项。有未保存修改时先确认离开。
- 一个页面保留一个明确主操作；低频操作收入“更多”。危险操作与普通操作在文案和样式上有区分。
- 1280px 下允许宽表格局部横向滚动，页面整体不出现横向溢出。

### 6.2 列表、数据与导出

- 所有完整列表显示总条数，支持 10 / 20 / 50 条分页；默认采用系统设置。排序未另作规定时使用创建时间倒序。
- 姓名、部门、金额、状态、日期等信息使用统一格式；列表长文本单行省略，悬停可看全，详情完整展示。
- 日期为 `YYYY-MM-DD`，时间为 `YYYY-MM-DD HH:mm`，统一使用 UTC+8。金额示例：`¥12,680.00`。
- 采购单号使用 `CG-YYYYMMDD-四位序号`；资产编号使用 `ZC-YYYYMMDD-四位序号`。编号自动生成且唯一，删除后不复用。
- 导出为 CSV，覆盖当前权限和筛选条件下的全部结果，按当前排序输出，不限当前页，不包含操作列和复选框。无数据时禁用并说明“暂无可导出数据”。
- 采购、资产导出采用当前表格的业务列；报表导出采用汇总表字段及合计行。文件名包含页面名称和基准日期，中文可正常打开。
- 保存、审批、启停用等成功后，相关列表、详情、计数、图表和日志同步更新；失败时不提前改变最终状态。

### 6.3 站内通知

通知入口使用顶部下拉面板，展示最近 10 条通知、未读数和“全部标为已读”，不单独增加通知中心页面。

通知仅来自审批通过或驳回，内容包含申请标题、结果和时间；驳回附简短原因。每人只能看自己的通知。点击后标记已读并进入申请详情。无通知时显示“暂无通知”。系统关闭结果通知后不创建新通知。

### 6.4 表单与操作反馈

- 必填项有统一标记。提交时在错误字段下说明原因，并定位到首个错误；不只弹出“提交失败”。
- 成功提示说明具体结果，例如“资产已分配给林晓”；通用失败提示提供重试方向，详细错误保留在相关区域。
- 正在保存、提交或删除时禁用重复触发。列表刷新不丢失有效筛选；删除后当前页为空时退到上一页。
- 原生格式错误、长度超限、重名、未选择必填项等，在当前页面解决，不进入新错误页面。
- 页面内单次修改失败后保留用户输入；用户主动取消修改时恢复上次已保存内容。

### 6.5 必须设计的状态

| 状态 | 展示与操作 |
| --- | --- |
| 首次加载 | 列表、卡片或表单使用与布局对应的骨架；不短暂闪现错误零值 |
| 没有任何业务数据 | 解释当前为空的原因；有创建权限时给出创建入口 |
| 筛选无结果 | 显示“未找到符合条件的数据”，提供重置筛选 |
| 加载失败 | 区域错误提示与“重试”；已有筛选和有效输入保留 |
| 无权限 | 无权限说明和返回工作台入口 |
| 记录不存在 | “记录不存在或已被删除”，提供返回来源列表；无权限记录不能借此泄露内容 |
| 处理中 | 当前操作按钮显示处理状态，防止重复操作 |
| 成功 / 失败 | 成功给出结果；失败说明原因并保留可重试内容 |

异常状态至少在采购列表和采购表单各实现一个可复现样例。测试环境应能明确触发一次列表加载失败和一次提交失败，触发后只影响下一次对应操作；控制方式可放在测试工具中，无须增加业务页面。

### 6.6 基础可访问性

状态必须同时使用文字与颜色；图标按钮提供名称；表单标签明确；键盘焦点可见。弹窗和抽屉打开后将焦点移入，关闭后返回触发按钮。有未保存修改时，按 Esc 与点击取消遵循相同确认规则。

测试环境统一使用 **2026-09-08** 为演示基准日，日期默认值、日期校验和统计范围均以此计算。新增操作也记录在该演示日期，并保留先后顺序，避免运行日期变化导致测试数字漂移。

| 数据 | 初始数量 | 必须包含的分布 |

推荐固定演示身份：林晓（申请人 / 产品设计）、陈予（审批人 / 行政）、顾言（审批人 / 财务）、许岚（管理员 / 行政）。另安排一名无申请、无资产的启用成员，用于验证空工作台。

必须保留以下可定位样本：

- 林晓的一张草稿：标题已填，其余信息不完整，可验证保存与提交校验的区别。
- 林晓的一张待审批申请：明细含 3 行，带附件，供审批通过测试。
- 林晓的另一张待审批申请：供驳回和复制测试。
- 陈予提交的一张待审批申请：陈予不能审批，顾言可以审批。
- 一张关联停用供应商的已通过申请：历史详情可正常查看。
- 一张选择了已停用供应商的草稿：提交时要求重新选择或清空。
- 一家初始启用、同时关联已提交申请与草稿的供应商：专门用于先停用、再核对历史与草稿的 T10 用例。
- 一件闲置资产：可分配给林晓，再验证归还。
- 一条接近长度上限的标题、一条 5 行采购明细申请，以及六位数金额的申请。

指标、图表、表格和详情均从这套数据计算，禁止分别编写互不对应的展示数字。采购预计金额与资产实际购入金额是两种独立数据，不要求相等。

## 8. 验收用例

以下 15 条构成本版验收范围。每次独立执行一轮前恢复演示数据；涉及状态变化的用例按表中顺序执行，必要时选择不同样本。

| 编号 | 操作场景 | 通过标准 |
| --- | --- | --- |
| T01 | 切换申请人、审批人、管理员；尝试直接访问无权限页面 | 菜单、按钮、数据范围正确；越权访问被拦截；管理员不能审批 |
| T02 | 采购列表搜索并组合两个筛选；排序、翻页，再重置 | 结果、总数、排序一致；重置清空条件并回第一页；详情返回保留原状态 |
| T03 | 新建申请，空提交；仅填标题保存草稿；再补齐明细提交 | 错误落到字段；草稿可保存；数量、金额计算准确；提交后变为待审批 |
| T04 | 添加到 5 行；选择附件并测试类型 / 大小超限；刷新草稿 | 行数限制明确；无效附件被拒绝；有效附件和已保存内容保留且可预览 |
| T05 | 编辑后尝试离开；触发一次提交失败；重试并连续点击提交 | 离开有确认；失败不丢输入；重试成功且不生成重复单据 |
| T06 | 审批人通过一张他人的申请，并尝试审批自己的申请 | 他人申请进入已通过，本人申请不可处理；详情、队列、记录和通知一致 |
| T07 | 无意见驳回，再填写意见驳回；申请人复制该申请 | 空意见被拦截；驳回原因可见；复制生成新草稿，原申请及记录保留 |
| T08 | 勾选草稿进行批量删除；尝试勾选其他状态和他人草稿 | 仅本人草稿可选；删除前确认数量；成功后条数和分页正确 |
| T09 | 管理员登记一件资产，关联已通过申请，分配给林晓，再归还 | 闲置 → 在用 → 闲置正确；本人资产列表、工作台数量和使用记录同步变化 |
| T10 | 停用指定的初始启用供应商，再打开其历史申请、新建表单和相关草稿 | 历史信息保留；新表单不可选；草稿提交要求处理停用选择 |
| T11 | 按部门查成员；新增一名测试成员，对其修改角色后停用；尝试停用当前管理员 | 组织筛选正确；新成员可用于演示；角色切换生效；停用成员不可使用；保护规则有效；保留两名初始审批人供后续用例使用 |
| T12 | 查看角色权限；保存系统名称、分页和通知设置；刷新；关闭通知后再审批 | 权限页只读且对应实际行为；设置持续生效；关闭后不生成新结果通知 |

## 9. 交付与实现顺序

设计交付包括 12 个页面，复用新建 / 编辑布局，并补齐采购表单错误态、审批抽屉、资产分配弹窗、危险操作确认及第 6.5 节通用状态。视觉风格可自行确定，信息层级、金额可读性、操作主次与状态可辨认性必须明确。

开发可按以下顺序完成，但最终交付仍覆盖本文件全部范围：

1. **先完成业务闭环：**页面框架、身份切换、采购列表 / 表单 / 详情、单级审批；对应 T01–T08。
2. **再补充典型页面：**资产、供应商、报表、组织、角色、设置和日志；对应 T09–T13。
3. **最后统一状态与体验：**错误重试、空状态、持久化、窄桌面展示与键盘操作；完成 T14–T15，并复核前序用例。

本产品的测试价值在于同一套业务数据穿过多种页面后依然保持一致。不要为了让每个按钮显得丰富而增加新业务，也不要让已列出的按钮只产生提示、没有对应的数据结果。
