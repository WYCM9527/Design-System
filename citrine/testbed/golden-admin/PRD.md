# 黄金后台 · 本地生活运营平台 — 产品文档（设计系统实测版）

> 这是一份**虚拟**产品文档。它存在的唯一目的，是给 `seeds/brand-yellow-e` 设计系统提供一个足够真实、又足够小的实测项目：覆盖中后台绝大多数页面类型、组件与状态，同时把交互深度压到"一页一个主任务、每个状态只出现一次"。所有业务数字、名称、流程都是编的，不要在其他场景引用。
>
> 版本 0.1 · 2026-09-08 · 配套设计系统 1.0.0-rc.3 起，现为 1.0.0

## 1. 产品定位

黄金后台是一家本地生活平台（外卖 + 到店）的内部运营系统。运营同学每天在这里处理订单异常、审核商户资质、配置营销活动、调度骑手、查看经营数据。它是典型的"高频、多表、重表单"中后台：使用者一天盯屏 6 小时以上，Windows 笔记本 + 1920×1080 或 1366×768 外接屏为主。

四个角色（角色决定菜单可见性与部分按钮权限，是唯一的权限维度）：

| 角色 | 能做什么 | 用来测什么 |
| --- | --- | --- |
| 管理员 | 全部 | 完整菜单 |
| 运营 | 订单、商户、营销、骑手；看不到财务结算 | 403 结果页、按钮级禁用 |
| 审核员 | 只有商户审核与订单查看 | 缩短的菜单、只读表单 |
| 财务 | 只有数据看板与结算 | 图表页、导出 |

## 2. 范围控制原则

为了让一轮验证在半天内做完，本文档对复杂度设了硬上限：

- 页面总数 **11 个**（P0 七个、P1 四个），每页一个主任务。
- 单个表单字段数 **≤ 12**；没有多步向导；没有拖拽、没有实时推送、没有地图。
- 列表页的四种非正常状态（加载中 / 空 / 出错 / 无权限）**各只需在一处**完整实现，其余页面复用。
- 弹窗只有三种：确认弹窗、表单弹窗、详情抽屉；每种在文档里各出现一次，其他地方引用同一规格。
- 图表只用四种：折线、柱状、环形、排行条。
- 不做移动端；最小支持宽度 1366px，侧栏可折叠。
- 暗色与紧凑密度是全局开关，不是页面功能；每页都要在三种模式下能看。

## 3. 全局框架

### 3.1 布局

- 左侧固定侧栏（200px，可折叠到 64px 只留图标）；顶栏 56px；内容区左右留白 24px。
- 顶栏从左到右：面包屑 · 全局搜索框（占位"搜索订单号 / 商户 / 骑手"）· 通知铃铛（带未读数徽标）· 暗色开关 · 密度开关 · 用户头像（点开下拉：个人中心 / 切换角色（测试用）/ 退出登录）。
- 侧栏菜单三组：**概览**（工作台、数据看板）、**业务**（订单管理、商户管理、营销活动、骑手调度）、**系统**（通知中心、成员与角色、个人中心）。当前项为深黑反转块 + 左侧品牌色指示条，图标保持线性；侧栏内不放计数气泡，待处理数在工作台与列表页头展示（第一轮反馈后修订）。
- 面包屑最多三级；列表页 → 详情页用面包屑返回。

### 3.2 全局状态

| 状态 | 出现位置 | 规格 |
| --- | --- | --- |
| 加载中 | 列表首屏、图表 | 骨架屏（表格 5 行、图表一块）；按钮提交中转圈并禁用 |
| 空 | 列表筛选无结果 | 插图 + 一句话 + 一个恢复动作（"清空筛选"） |
| 出错 | 接口失败 | 卡片内错误提示条 + "重试"按钮；不弹全屏 |
| 无权限 | 直接访问无权页面 | 403 结果页；无权按钮显示为禁用并带 Tooltip"需要 xx 权限" |
| 成功反馈 | 保存、提交、删除 | 右上角 Toast，3 秒自动消失 |
| 需要注意 | 资质即将过期等 | 页面顶部提示条，可关闭 |

### 3.3 通用表格规格

- 默认每页 20 条，可切 10 / 20 / 50；表头可排序列显示排序指示；首列勾选框 + 末列"操作"固定。
- 行内操作最多三个文字链接，多于三个收进"更多"下拉。
- 选中行数 ≥ 1 时表格上方出现批量操作条（已选 N 项 · 取消选择 · 批量按钮）。
- 状态列统一"浅色胶囊 + 文字"（不带圆点，第一轮反馈后修订），金额与时间列等宽数字右对齐（金额）/ 左对齐（时间）。
- 紧凑模式下行高、单元格内边距收紧，列不变。

### 3.4 通用表单规格

- 横向表单，标签右对齐、列宽统一；两列布局，超长字段（备注、上传）占整行。
- 必填星号在标签后；校验在失焦时进行，错误文案显示在字段下方；提交时滚动到第一个错误。
- 只读字段用只读底色（可复制），禁用字段整体变淡。
- 表单页底部固定操作区：取消 / 保存草稿 / 提交。
- 单列表单最大宽度 720px；表单弹窗宽 640px；确认弹窗宽 420px；抽屉宽 480px。

## 4. 页面清单（P0）

### 4.1 登录页

**目标**：进入系统。**唯一一次允许大面积品牌黄。**

- 左侧品牌区（品牌黄底、深字）：产品名、一句 slogan、版本号；右侧白色登录卡（400px）：账号、密码、"记住我"、登录按钮（大号）、"忘记密码"链接。
- 状态：账号或密码为空 → 字段下方错误文案；密码错误 → 卡片顶部错误提示条；登录中 → 按钮转圈禁用。
- 不做验证码、不做扫码（放一个"企业微信登录"的次要按钮占位即可）。

### 4.2 工作台

**目标**：一屏看到今天要处理的事。

- 顶部提示条（"3 个商户资质将在 7 天内过期"，可关闭，右侧"查看列表"链接）。
- 四张统计卡：今日订单（高亮卡，品牌黄底）、GMV、待审核商户、骑手在线；每张带较昨日涨跌（涨绿跌红）。
- 左：订单趋势折线图（近 14 天，本周 / 上周两条线，图例）；右：待办列表（5 条，每条一个状态徽标 + 时间 + 跳转链接）。
- 下：最近异常订单表（5 行精简表格：订单号、商户、状态、金额、操作），表头带"查看全部"链接。
- 状态：图表加载骨架；待办为空时显示空状态（"今天没有待办"）。

### 4.3 订单管理（列表）

**目标**：找到一单并处理它。这是**表格规格的完整实现处**。

- 筛选栏：关键词（订单号 / 商户 / 手机号）、状态下拉、城市下拉、下单时间范围、"我负责的"分段切换；查询 / 重置。选中的筛选条件以可删筹码显示在筛选栏下方。
- 表格列：勾选 · 订单号（等宽，第二行灰色副行显示时间与骑手）· 商户 · 城市 · 金额（等宽右对齐，可排序）· 下单时间（可排序）· 状态 · 骑手 · 配送时长 · 评分 · 操作（详情 / 改派 / 更多 ▾：催单、取消订单）。首列与操作列固定，中间列可横向滚动。
- 状态词汇：待接单（warning）、配送中（info）、已完成（success）、已取消（error）、草稿（neutral）——正好覆盖五种状态色。
- 批量操作条：批量改派、导出所选、批量取消（危险）。
- 四种非正常状态在此页完整实现：骨架屏、空状态、错误重试、（财务角色访问时）403。
- "改派"打开**改派抽屉**（见 4.4）；"取消订单"打开**确认弹窗**（标题、一句说明、"再想想" / 危险按钮"确认取消"）。

### 4.4 订单详情 + 改派抽屉

**目标**：看清一单的全部信息，必要时改派骑手。

- 页头：订单号（等宽）+ 状态徽标 + 操作按钮（打印 · 取消订单）。
- 步骤条：已下单 → 商户接单 → 配送中 → 已送达（当前步骤品牌黄，完成步骤绿）。
- 两栏：左侧描述列表（商户、城市、金额、较上单涨跌、骑手、预计送达、用户备注——备注是长文本，测试多行对齐）；右侧时间线（4～6 条事件，节点颜色按事件语义）。
- 标签页：商品明细（简单表格 3～5 行）· 支付信息（描述列表）· 操作日志（时间线）。
- **改派抽屉**（480px）：顶部标题 + 关闭；列表展示 6 位附近骑手（头像、姓名、距离、评分、当前单量），单选；底部取消 / 确认改派。确认后 Toast"已改派给 xx"，抽屉关闭，详情页骑手字段更新。
- 打印：打印本页时隐藏侧栏、顶栏、按钮，黄色底转为边线（测试 `print.css`）。

### 4.5 商户管理（列表 + 新建 / 编辑表单页 + 审核弹窗）

**目标**：录入一个商户并让它通过审核。这是**表单规格的完整实现处**。

- 列表：与订单列表同规格，列更少（商户名、编号、经营类型、城市、状态、入驻时间、操作：编辑 / 审核 / 停用）；状态：待审核、已上线、已驳回、已停用（neutral）。
- **新建 / 编辑表单页**（两列横向，最多 12 字段）：商户名称*、商户编号（编辑时只读）、经营类型*（单选：餐饮 / 生鲜 / 零售）、结算周期（分段：T+1 / T+7 / 月结）、联系人*、联系电话*（格式校验）、城市*（下拉）、地址、配送半径（滑杆）、起送金额（数字步进）、经营标签（可删标签 + 添加）、营业执照*（上传，拖入态）、备注（多行）。底部：取消 / 保存草稿 / 提交审核。
- 校验演示：电话格式错误、必填缺失、执照未上传三种错误文案同时出现一次。
- **审核弹窗**（表单弹窗 640px）：只读的商户摘要（描述列表）+ 审核结论（单选：通过 / 驳回）+ 驳回原因（选"驳回"时才出现，必填多行）。通过 → 成功 Toast；驳回 → 列表状态变"已驳回"。
- 审核员角色进入编辑页时，全部字段只读，底部只剩"返回"。

### 4.6 营销活动

**目标**：配置一个满减活动并上线。测试**状态流转与表单弹窗**。

- 列表：活动名、类型（满减 / 折扣 / 赠品）、投放范围、预算 / 已用（进度条）、时间范围、状态（草稿 / 待审核 / 进行中 / 已结束 / 已下线）、操作（编辑 / 上线 · 下线 / 复制）。
- 新建用**表单弹窗**（640px）：活动名称*、类型*、满减规则（两个数字输入：满 X 减 Y）、预算上限*（数字，出错示例：负数）、投放城市（多选下拉，显示为标签）、活动时间*（范围）、同步到 App 首页 Banner（开关）、结束自动下线（开关）。
- 上线 / 下线走确认弹窗；进行中的活动在列表里有预算进度条（品牌色填充）。
- 卡片视图切换（列表 / 卡片）：卡片版每张显示名称、状态徽标、预算进度、时间——测试同一数据两种密度的排版。

### 4.7 系统 · 成员与角色

**目标**：给一个成员分配角色。测试**权限矩阵与开关组**。

- 左右结构：左侧角色列表（管理员 / 运营 / 审核员 / 财务，可新增）；右侧该角色的权限矩阵——按菜单分组的勾选框（订单：查看 / 改派 / 取消；商户：查看 / 编辑 / 审核 …），组标题带"全选"。
- 成员表：头像、姓名、账号、角色（标签）、状态（启用 / 停用 开关）、最近登录、操作（编辑角色 / 重置密码 / 移除）。
- "移除成员"用确认弹窗（危险）。
- 状态：把当前登录账号自己的角色改成"财务"，立刻演示订单菜单消失与 403。

## 5. 页面清单（P1）

### 5.1 数据看板

**目标**：看一周经营情况。测试**四种图表 + 图表调色板 + 大数字**。

- 顶部：时间范围（近 7 天 / 近 30 天 / 自定义）+ 城市筛选 + 导出按钮。
- 第一行四个统计卡（大数字 + 涨跌）。
- 第二行：订单量折线（三城市三条线，测分类色 1～3）· 品类占比环形图（六个品类，测分类色 1～6）。
- 第三行：商户 GMV 排行条（前 10，测顺序色）· 时段热力（7 天 × 24 小时格子，测顺序色 1～5）。
- 图表内不放主按钮；图例用次要文字色。
- 财务角色可见"结算"标签页：一张带合计行的表格 + 导出。

### 5.2 骑手调度

**目标**：看骑手状态并处理离线。保持轻量，**不做地图**。

- 顶部状态卡：在线 / 忙碌 / 离线三个数字；下方骑手表（头像、姓名、状态圆点、当前单量、今日完成、评分、最近活跃、操作：查看 / 派单 / 强制下线）。
- "派单"用小型选择弹窗（420px，单选待派订单）；"强制下线"用确认弹窗。
- 状态列三色：在线 success、忙碌 warning、离线 neutral。

### 5.3 通知中心 + 公告详情

**目标**：读完一条公告。测试**列表密度 + 长文排版**。

- 通知列表：分"系统 / 审核 / 运营"三个标签页；每条：类型图标、标题、摘要一行截断、时间、未读圆点；"全部标为已读"。
- 公告详情页：标题（大号）、发布人与时间、正文 6～8 段（段落行高、小标题、一个有序列表、一张表格、一段引用）——这是全站唯一的长文页面。

### 5.4 个人中心 + 异常页

- 个人中心：头像上传、姓名、账号（只读）、手机号、通知偏好（三个开关）、修改密码（三个密码框 + 强度提示条）；保存后 Toast。
- 403 / 404 / 500 三个结果页：大号代码、标题、一句说明、"返回首页" + 一个情境动作（403 是"申请权限"，500 是"重试"）。

## 6. 数据与词汇

- 模拟数据量：订单 128 条、商户 36、骑手 24、活动 12、成员 9、通知 30、公告 3。
- 状态词汇表（全站统一，对应五种状态色）：
  - success：已完成、已上线、进行中（骑手在线）、通过
  - warning：待接单、待审核、忙碌、即将过期
  - error：已取消、已驳回、失败
  - info：配送中、处理中
  - neutral：草稿、已停用、已结束、离线、已过期
- 金额一律 `¥ 1,286.00`，等宽数字；时间 `2026-09-08 14:02`；手机号中间四位打码。
- 涨跌：涨绿跌红（公司约定，与 A 股相反）。

## 7. 非功能要求

- 最小宽度 1366px，侧栏在 ≤ 1440px 时默认折叠。
- 亮色 / 暗色 / 紧凑三种模式全站可切，切换不刷新页面。
- 不依赖网络字体；Windows 上中文由微软雅黑显示，中文字号不小于 12px。
- 所有文字对底色对比度 ≥ 4.5:1（占位符除外）；所有可点击元素有可见焦点。
- 打印订单详情时可读（黄色底转边线，隐藏导航与按钮）。

## 8. 明确不做

多语言、移动端、地图、实时推送、拖拽排序、富文本编辑器、多步向导、Excel 在线编辑、数据大屏。

## 9. 设计系统验证矩阵

这张表是本文档存在的理由：每个页面负责验证设计系统的哪一部分。做完一页就在对应行打勾并记录问题。

| 页面 | 验证的 token / 组件 | 验证的状态 |
| --- | --- | --- |
| 登录页 | `bg.brand` / `text.on-brand` / `text.hero` / `control.height.lg` / `layout.auth.card-width` | 字段错误、提示条错误、提交中 |
| 工作台 | 统计卡（高亮卡 `on-primary-muted`）、`data.increase / decrease`、折线图 `chart.1 / 2`、待办徽标、提示条 | 图表骨架、待办空态 |
| 订单列表 | 表格全规格（排序、固定列、批量条、筹码、`bg.selected-subtle`）、五种状态色、`text.numeric.variant`、分页尺寸 | 骨架 / 空 / 错误 / 403 四态 |
| 订单详情 | 步骤条、描述列表、时间线、标签页、抽屉 `layout.drawer.width` + `elevation.modal`、确认弹窗 `layout.modal.width.sm`、打印 | 抽屉单选、Toast |
| 商户表单 | 横向表单 `layout.form.label-width` / `max-width`、单选、分段、滑杆、步进、上传拖入、可删标签、只读 `bg.readonly`、校验错误 | 三种错误同屏、审核员只读态 |
| 商户审核弹窗 | 表单弹窗 `layout.modal.width.md`、条件显示字段、`action.danger` | 驳回流程 |
| 营销活动 | 进度条、开关、多选标签、列表 / 卡片切换、状态流转 | 负数校验 |
| 成员与角色 | 权限矩阵勾选框组、开关列、标签、危险确认 | 自我降权 → 403 |
| 数据看板 | `chart.1–6`、`chart.sequential.1–5`、环形图、排行条、热力格、大数字、导出 | 时间范围切换 |
| 骑手调度 | 状态圆点三色、小型选择弹窗、头像 | 强制下线确认 |

## 10. 验收方式

1. 每页在亮 / 暗 / 紧凑三种模式下各截一张图，放进 `testbed/golden-admin/shots/`。
2. 项目内跑设计系统守卫：`guard` 为 current，`status` 采用率 100%，剩余字面量全部登记豁免并写理由。
3. 对比度脚本跑一遍全部文字 / 底色配对。
4. 在一台 Windows 1x 屏的机器上过一次登录页、订单列表、商户表单——看描边、字重、hover 是否成立。
5. 每发现一个设计系统缺口，记到 `CHANGELOG` 的"实测反馈"段，按批修。
