# 剧本 · 验收失败归因

原则：**先归因到层，再改**。层次从下到上：token → 桥接（组件库 / 图表）→ 配方（recipes / 配方组件）→ 页面 → 豁免。快照只读，桥接 / 配方 / token 的修复都属于上游——项目里能做的是页面层修复、工作副本（scope / 豁免）与向上游提案。

| 验收报什么 | 大概率是哪层 | 项目里怎么办 |
| --- | --- | --- |
| 低对比（lowContrast） | 页面用错 token（如 muted 文字放深底）；或组件库默认色没被桥接接管 | 页面层换正确 token；若是组件库默认色 → 向上游提桥接修复，临时可在 `app.css` 用 token 覆盖并注明「等上游 X 版删除」 |
| 无可访问名称（noName） | 页面：图标按钮少 `aria-label` / `title` | 页面补 |
| 命中区过小（tinyTargets） | 组件库默认尺寸（桥接层）或页面自绘小按钮 | 自绘的按配方改；组件库的向上游提（参考：桥接可用伪元素外扩不改视觉） |
| 状态切换新引入品牌色 / 悬停对比掉档 / 外来颜色（组件走查） | 几乎都是桥接层（组件库某状态没接管） | 向上游提，附走查输出的选择器与颜色值；不要在页面用 `!important` 压 |
| 横向溢出 / 窄屏不折叠 | 页面布局没用配方壳层，或页面自己写了固定宽度 | 页面层修，宽度用 layout token |
| Tab 焦点 NO RING | 桥接层（组件的 focus 样式被组件库吃掉）或页面自绘可聚焦元素 | 自绘的加配方焦点样式；组件库的向上游提 |
| guard 非 current | 手改了 `design-system/dist/`，或 tokens 源与 dist 不同步 | 重跑 build-tokens；谁改了 dist 撤销谁 |
| steward status 有字面量债 | 页面写了硬编码 | 按 DESIGN 换 token；确属有意的登记 `exemptions.json`（带理由） |
| 升级后像素变化 | minor 版本的 token 变更，预期行为 | 对照 CHANGELOG 逐条核对；只有「变化与 CHANGELOG 对不上」才是 bug |

## 「配方不够用」的处理路径

1. 确认 DESIGN 配方表真的没有可类推的行（先找最接近的）。
2. 写清提案：场景、期望形态、建议层（token / 桥接 / recipes / 配方组件）、涉及的既有 token。
3. 交用户决定：向上游仓库提 issue / PR（种子改动走上游的 CHANGELOG 与版本），或在本项目工作副本做 scope（steward 流程）。
4. 等不及上游时的临时写法放 `app.css`，注释里写「临时，等 <id> 上游」——升级后清理。
