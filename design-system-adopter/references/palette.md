# 剧本 · 换颜色（颜色主题）

目标：项目换一套品牌色（如玫瑰金 → 蓝），结构（间距 / 字号 / 圆角 / 组件 / 配方）一点不动。机制：种子的 `palettes/<id>.json` 一个颜色一个文件，只换品牌色原语（身份文件 `palettes.group`，通常 `color.brand.*`）和 `palettes.roles` 登记的角色指向；`ds.mjs palette` 把它套进工作副本、记进 `.adopter.json`、重建 token。

## 步骤

1. `ds.mjs palette --list`：列出官方颜色（项目能直接用）和只在效果预览里试的颜色，● 标当前。用户拿不准时把命令打印的预览链接（`<效果预览>?palette=<id>`）给他先看。
2. 新项目：`init --palette <id>` 接入时一步套好；已接入的项目：先 `ds.mjs palette <id> --dry-run` 给用户看改哪些文件、这套颜色登记了哪些对比度例外，同意后去掉 `--dry-run`。
3. 换完会自动用 steward 重建 dist（范围根项目还会重生成范围包）；接着 guard（current）→ 验收命令。品牌色变了，截图基线跟着变，属预期。
4. 非 Node 项目：`ds.mjs export --to <dir> --palette <id>`（之后重导出沿用；换回默认颜色就写默认颜色的 id）。范围根且没有工作副本 dist 时用 `scope --palette <id>`；有工作副本时颜色跟工作副本走，用 `palette` 换。

## 判断要点

- **只用官方颜色**。用户要清单外的颜色（列表里「只在效果预览里试」的，或自己挑的色值）：先 `ds.mjs propose --layer palette --title "…" --scene "…"` 提案，上游转正后再换；用户明确只想在本项目先试才加 `--unofficial`，并告诉他升级时上游可能调整或删掉它。
- **不手改品牌色原语和登记的角色**：这些键归调色盘管，`status` 会报「被手改过」，换色和升级都会覆盖它们。想微调某一档，在效果预览右下角「规范调节」里调好、导出清单，作为提案交上游。
- `palette` 因「被手改过」拦下时，先问用户那些改动还要不要（多半是早先绕过规范改的品牌色）：不要就 `--force`，要就先提案。
- **升级不用管颜色**：`upgrade` 先摘下调色盘再做三方合并，合并完按新版本重套，上游调整了这套颜色也会跟上。项目用的颜色在新版本里被删了，`upgrade` 会在动手前拦下，让用户先换一套还在的颜色。
